# 問い合わせ・案件管理ツール 基本設計書

## 1. 文書情報

- 文書名：問い合わせ・案件管理ツール 基本設計書
- バージョン：Ver1.0
- 作成日：2026-09-21

- 想定用途：ポートフォリオ用デモアプリ、業務支援ツール開発実績の提示

---

## 2. プロジェクト概要

### 2.1 目的

顧客・取引先・社内などから受け付けた問い合わせを登録し、必要に応じて案件化し、
担当者・進捗・優先度・対応履歴・期限を一元管理する業務支援ツールを作成する。

単なる問い合わせ一覧ではなく、以下の一連の業務フローを1つの画面群で管理できることを目標とする。

1. 問い合わせ受付
2. 内容確認
3. 担当者割当
4. 案件化
5. 対応・進捗管理
6. 対応履歴記録
7. 完了・クローズ
8. 集計・可視化

---

## 3. 想定利用シーン

- 顧客からの問い合わせ受付
- 営業案件の管理
- 社内ヘルプデスク
- 修理・保守受付
- クレーム・要望管理
- 小規模事業者の顧客対応管理

---

## 4. 想定ユーザー

### 4.1 一般担当者

- 問い合わせを登録する
- 自分の担当案件を確認する
- 対応内容を記録する
- ステータスを更新する

### 4.2 管理者

- 全問い合わせ・案件を確認する
- 担当者を割り当てる
- 優先度を変更する
- 期限超過案件を確認する
- KPI・集計結果を見る

※ Ver1.0ではログイン・権限制御は必須実装としない。
将来拡張として管理者／一般ユーザー権限を追加可能な構成とする。

## 5. 業務フロー

```text
問い合わせ受付
    ↓
問い合わせ登録
    ↓
内容確認
    ↓
担当者割当
    ↓
案件化が必要か判定
    ├─ No → 問い合わせ対応 → 完了
    └─ Yes
          ↓
        案件化
          ↓
        対応履歴追加
          ↓
        進捗・期限管理
          ↓
        完了
          ↓
        クローズ
```

## 9. ステータス定義

### 9.1 問い合わせ

| ステータス | 意味 |
|---|---|
| 未対応 | 登録済み・未着手 |
| 対応中 | 担当者が対応中 |
| 保留 | 顧客回答待ち・社内確認待ち等 |
| 完了 | 問い合わせ対応完了 |

### 9.2 案件

| ステータス | 意味 |
|---|---|
| 未着手 | 案件化済み・未着手 |
| 対応中 | 対応作業中 |
| 保留 | 外部回答待ち等 |
| 完了 | 案件完了 |

---

## 10. 優先度定義

| 優先度 | 目安 |
|---|---|
| 低 | 通常対応で問題なし |
| 中 | 標準対応 |
| 高 | 早めの対応が必要 |
| 緊急 | 最優先対応 |

## 14. KPI定義

| KPI | 算出 |
|---|---|
| 総問い合わせ件数 | 全問い合わせ数 |
| 未対応件数 | status = 未対応 |
| 対応中件数 | status = 対応中 |
| 完了件数 | status = 完了 |
| 完了率 | 完了件数 ÷ 総件数 |
| 期限超過件数 | due_date < 今日 かつ 未完了 |
| 平均対応日数 | 完了日 - 受付日 |
| 案件化率 | 案件化件数 ÷ 問い合わせ総数 |

## 26. 開発開始時の基本方針

1. まずPhase 1のみ実装する
2. 各Phase完了時にpytestを実行する
3. 意図しない既存機能変更を行わない
4. Phase単位でCommit / Pushする
5. 設計変更が発生した場合は本設計書も更新する
6. UIより先にデータ整合性を優先する
7. 1回の実装範囲を広げすぎない
